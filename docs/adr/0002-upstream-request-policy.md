# 上游请求策略的分层配置与渐进式演进

## 状态

已采纳

## 背景

不同站点可能同时提供 OpenAI Compatible 和 Anthropic Messages 接口，但同一个模型在不同接口上的请求体、endpoint、流式行为和提示词缓存行为并不一定等价。

本次排查确认：Command Code 的 `deepseek/deepseek-v4-flash` 在 Claude Messages 下游请求中，如果中转站把上游 Chat Completions 也设置为流式，请求缓存表现明显变差。将上游 Chat Completions 改为 `stream:false`，再由中转站转换为下游 SSE 后，重复请求可以恢复缓存命中。

因此，“下游是否流式”和“上游如何请求”必须是两个独立概念。不能因为下游客户端要求 SSE，就无条件把上游请求设置为流式，也不能把 endpoint 选择和流式模式混成一个配置项。

## 决策

### 当前阶段：账号级 JSON 作为兼容层

当前先使用账号记录中的 `extra_config` 保存小范围、明确的例外策略：

```json
{
  "proxy": {
    "upstreamStreamMode": {
      "deepseek/deepseek-v4-flash": "buffered"
    }
  }
}
```

该策略只对保存它的账号、匹配的实际模型，以及 Claude Messages 下游的流式请求生效。缺少配置、模型不匹配或配置值非法时，必须回退到 `inherit`，不能改变其他账号、站点或模型的默认行为。

现阶段不新增策略表，也不把该设置放进全局环境变量。原因是当前需求只有一个站点账号和一个模型，账号级范围最小，便于验证、回滚和控制影响面。

### 长期阶段：结构化 Web 配置

账号页面应提供结构化的“高级代理策略”配置，用户不需要直接编辑 JSON。第一阶段可以继续将结构化表单写入现有 `extra_config`，但必须由后端负责校验和合并，不能让前端任意覆盖整段 JSON。

长期策略字段至少应独立表达：

- 适用模型：精确模型名，后续再考虑模型模式；
- 适用下游协议：Claude Messages、OpenAI 或全部；
- 上游 endpoint 偏好：自动、Chat、Messages、Responses；
- 上游流式模式：继承、流式、缓冲非流式；
- 启用状态和规则优先级。

### 未来阶段：站点默认与覆盖关系

当多个账号或站点出现同类需求后，再将策略抽象为独立的站点/模型策略，并采用以下优先级：

`全局默认 -> 站点默认 -> 站点模型规则 -> 账号覆盖`

默认值必须保持自动兼容。强制 endpoint 只能改变候选顺序或经过能力校验后生效；如果上游模型明确不支持该 endpoint，应回退或返回清晰错误，不能静默发送错误协议。

## 影响与约束

- 同一个模型在不同上游之间调用，缓存通常不共享，策略必须绑定到站点或账号上下文，不能只按模型名做全局配置。
- endpoint 选择和上游流式模式分别记录、分别诊断；`buffered` 不代表强制使用 Chat endpoint。
- 日志和调试信息应记录最终采用的策略、endpoint、上游 `stream` 值和缓存字段，便于区分上游能力问题与中转请求形态问题。
- 专用策略 API 应避免触发与代理策略无关的模型刷新；现有 `extra_config` 读逻辑保留，供历史数据兼容和迁移使用。

## 后续工作

1. 在账号编辑页增加当前策略的结构化表单。
2. 增加后端策略读写接口和严格校验，保留旧 JSON 的读取兼容。
3. 出现多个站点的共性规则后，再增加站点级默认策略和独立策略表。
4. 为策略决策、endpoint 选择和缓存结果增加可观测字段与回归测试。
